# Provenance audit (2026-10-25)

Purpose: before choosing a licence or sharing the repository, record where every part of
it comes from, with particular attention to the reverse-engineering (REA/Ghidra) work on
the Rocksmith+ Workshop that started the project. This is a factual record for review,
not legal advice.

## Scope and method

- All 423 tracked files and the full Git history of this repository (`open-chart-editor`).
- The decompilation and research material lives **outside** this repository, in the parent
  folder (`UGCTool.c`/`.h`, `ghidra-project`, REA snapshots, `research/`); `research/` and
  `verification/` inside the repository are ignored by Git.
- Checks run:
  1. Every string literal of 12+ characters in the decompiled R+ Workshop (`UGCTool.c`/`.h`,
     1,007 literals) searched for in every tracked file.
  2. Tracked files searched for decompiler artefacts (`FUN_xxxxxx`, `DAT_`, `LAB_`) and for
     notes saying code was ported or decompiled.
  3. Every non-code file (data, fixtures, schemas) traced to its origin.
  4. Git history checked for any file ever added (424 paths): no game assets, audio,
     packages, charts, decompilation or research files were ever committed. The only file
     ever deleted (`browser-last.png`) is a screenshot of this editor's own demo project.

## Findings

### No decompiled code or copied R+ Workshop text

- No decompiler artefacts in any tracked file.
- 34 of the 1,007 decompiled string literals occur in the repository. All are file-format
  identifiers the editor must read and write to interoperate (RS2014/R+ XML element and
  attribute names such as `phraseIterations`, `chordTemplates`, `slideUnpitchTo`,
  `lastConversionDateTime`; MusicXML tag names; one gear key), plus two short feature terms
  ("Force Destination Pitch", "Unpitched slide"). No messages, UI text or code were copied.
- Where behaviour was informed by observing the R+ Workshop, the code says so and states it is
  an original implementation: `src/zone-fit.js` ("NOT its decompiled algorithm"),
  `src/chord-tools.js` (observed context guard), README destination-pitch note
  ("REA-observed prerelease serialization").

## Items to review before publishing

1. **Licence and notices.** THIRD-PARTY-NOTICES.txt now credits Rocksmith2014.NET for the
   gear catalog and the FeedPak spec for the schemas, and lists vgmstream and jsonschema.
   Ship it with every copy.
2. **Look and feel.** The UI was deliberately modelled on the R+ Workshop's workflow ("R+ Workshop-style
   menus, timeline, inspector"; keyboard-shortcut familiarity audit). Functional similarity
   (features, shortcuts, workflow) is generally fine; copying distinctive visual expression
   (layouts, icons, wording, artwork) is not. Worth a visual review against the retail tool.
3. **Name and trademarks.** "Rocksmith", "Rocksmith+" and "R+" appear only to describe
   compatibility, and the notices disclaim affiliation. Done (2026-10-25): the project was
   named **Open Chart Editor (OCE)**, a name that does not echo
   "Rocksmith+ Workshop"; new exports use OCE names and earlier ones still open.
   Licence chosen: AGPL-3.0-only, the same as FeedBack.
4. **Gear display labels.** The catalog's labels are the game's gear names (via DLC Builder).
   If publication raises concern, keys could stay and labels be replaced by neutral ones.
5. **Reverse-engineering basis.** The `.rsw`, R+ XML and `metadata.json` knowledge was gained
   to make an independent program interoperate (UK CDPA s.50B / EU Software Directive art. 6
   cover decompilation for interoperability, within limits). Keep the decompilation and REA
   material out of any shared repository, as now.
6. **FeedBack project alignment.** FeedBack contributions carry a DCO sign-off; agree with the
   FeedBack maintainers how reverse-engineered format knowledge is handled before upstreaming.
